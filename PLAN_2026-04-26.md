## CRITICAL — blocks usage

### 0a. Original view mode shows the NN-clean FG (regression from purple-fix)
**Symptom:** clicking "Original" in the viewer shows a black-where-green-was image, not the actual unprocessed source frame.
**Cause:** today's purple-fix changed `fg.png` to be the NN-clean foreground. The viewer's Original mode reads from `fg.png` — so it now shows the keyed FG instead of the original.
**Fix:** panel writes `original.png` (raw frame) alongside `fg.png`; viewer Session loads `original.png` if present and uses it for Original view mode. Foreground mode keeps using `fg.png` (correct convention: Foreground = keyed clean FG).
**Effort:** small. Risk: low.

### 0b. Split view doesn't shrink the window when toggled off
**Symptom:** clicking Split widens the viewer window. Clicking Split again to go back to single view leaves the window stuck wide.
**Cause:** `_toggle_split()` resizes wider when checked but doesn't resize back when unchecked.
**Fix:** mirror the resize on the off-branch.
**Effort:** trivial.

### 0c. Matte view shows nothing visible (under investigation)
**Symptom:** clicking "Matte" view mode shows no white matte. Berto expects a white-on-black alpha visualization.
**Status:** root cause not pinned yet. Possibilities: SAM2 gate restricting matte to tiny region; despeckle eating it; or rendering bug. Need retest after fixing 0a/0b to confirm if it's still happening.

### 0. SCRUB RANGE produces empty mattes (in progress NOW)
**Symptom:** SCRUB RANGE keys 10 frames, scrub bar shows, but every scrub frame displays the checkerboard background (no actor). PROCESS RANGE on the same clip works fine.
**Root cause found:** in each `scrub/NNN/` directory, `alpha.png` is entirely zero, but `alpha_raw.png` has real matte data and `sam2_gate_raw.png` is ALSO entirely zero. The plugin's keying step does `alpha = alpha_raw * gate` — gate=0 → alpha=0 → empty matte.
**Why the gate is zero:** under investigation. SAM2 video propagation reports "N masks ready" in logs, but the saved gate file has zero pixels. Possibly a shape mismatch (gate is 4K, alpha is 720p) OR the mask values aren't surviving the float→uint8 cast.
**Effort:** small once root cause is pinned. Quick-fix fallback: have the viewer load `alpha_raw.png` when `alpha.png` is empty so the user can scrub immediately even if SAM2 misbehaves.

### 1a. Live preview viewer window — text squished, video cut off
**Symptom:** When the Live Preview viewer first opens, the bottom video preview area is cut off — user has to manually resize the window taller to see the keyed image. Also when the window is narrow, the slider row text (DESPILL, DESPECKLE, CHOKE, MARGIN, SOFTEN) gets visually squished. Numeric readouts overlap labels.
**Want:** opens at a default size that fully shows the video preview. Slider labels never squish — either the row preserves a minimum width, or the label/value sizes are fixed and only the slider track stretches.
**Fix approach:** set a sensible default `resize()` and `setMinimumSize()` on `PersistentWindow.__init__`. Set `setMinimumWidth` on the slider grid's first/last columns so labels and value readouts stay readable; only the middle (slider track) column is allowed to compress.
**Effort:** small. Risk: low — pure layout.
