## Real bugs (2)

### 1. AE host's session-dir writes are non-atomic
**File:** `ae_plugin/ae_processor.py:472, 473, 481` (cmd_cache)
**Severity:** medium

`cv2.imwrite()` for `fg.png`, `alpha.png`, `original.png` are plain non-atomic writes. The Resolve panel uses an `_atomic_imwrite` helper (write to `.tmp`, then `os.replace`) for the same files. The AE viewer's `Session.reload_pngs` even has a comment acknowledging the partial-read risk and tries to mitigate on the read side — but the fix belongs on the write side.

**Concrete failure modes:**
- Mild: AE viewer's poll loop reads while `cmd_cache` is mid-write → `_read_png_any_depth` returns None → viewer skips this tick. Recoverable.
- Worse: writes complete out of order — viewer gets new `fg.png` + new `alpha.png` + stale `original.png`. With **FG SOURCE = "source" engaged**, the viewer paints the new matte using the previous frame's source color until the next poll tick.

**Fix:** add the same `_atomic_imwrite` helper from the Resolve panel to `cmd_cache`. Even better: wrap fg/alpha/original under a single rendering lockfile or version-bump scheme so viewer reads atomically across all three.

### 2. MLX path: FG SOURCE substitution updates `fg` but not `comp` or `processed`
**File:** `CorridorKeyModule/backend.py:368-382` (_wrap_mlx_output + MLX adapter)
**Severity:** medium (latent on Berto's Windows machine; real on Apple Silicon)

After `_wrap_mlx_output` returns, the MLX adapter overwrites `out["fg"]` with the source plate, but `out["comp"]` (composite on checkerboard) and `out["processed"]` (premultiplied linear RGBA) were already built from the NN's FG inside `_wrap_mlx_output`. They keep the model's NN color. The torch path does this correctly because `_postprocess_torch` / `_postprocess_opencv` substitute `fg` BEFORE building `comp` and `processed`.

**Concrete failure mode:** `backend/service.py` writes `comp` and `processed` to disk as user-visible outputs (`comp_path`, `proc_path`). An Apple-Silicon user running `service.py` with FG SOURCE = "source" gets `Comp/*.png` and `Processed/*.exr` showing the wrong color — same yellow→pink shift the toggle was supposed to fix.

**Fix:** in the MLX adapter, do the substitution on the MLX raw output BEFORE `_wrap_mlx_output`, or apply the same substitution-then-rebuild logic that `_wrap_mlx_output` does internally.

## Minor / footguns (4)

### 3. `_is_hevc_file` caches negative probe results forever
**File:** `resolve_plugin/CorridorKey_Pro.py:987-1011`

If `cv2.VideoCapture` momentarily fails on first probe (network share down, file briefly locked), `is_hevc=False` is cached for the lifetime of the process. Later when the file is accessible the cache returns stale False and the user sees the yellow→pink shift again. Cache is process-lifetime only — minor.

**Fix:** cache only successful probes; skip caching on `release()` paths where `_probe.isOpened()` was False.

### 4. `write_plugin.py` is now a footgun
**File:** `write_plugin.py`

The refactor in `856f3ad` correctly removed the embedded plugin string. But `write_plugin.py` writes `CorridorKey.py` with a plain `open(..., 'w')` and no backup. `deploy.py` does both. If anyone forgets and runs the legacy `write_plugin.py`, they overwrite the live plugin with no recovery path.

**Fix:** either delete `write_plugin.py` (deploy.py supersedes it) or have it shell out to `deploy.py`.

### 5. `apply_sam2_gate` has no shape validation
**File:** `sam2_combine.py`

Helper is "single source of truth" for 7 active callsites. If any caller forgets to squeeze `mt` to 2D before passing it, `alpha * gate_use` silently broadcasts oddly or crashes. All existing callsites do squeeze (`_mt2d = mt[:, :, 0] if len(mt.shape) == 3 else mt`) — but a future caller wouldn't get a clear error. Comment claim "All 6 callsites must use this" is also off — there are 7 active callsites in HEAD.

**Fix:** add an `assert alpha.shape == gate.shape` (or auto-squeeze) inside `apply_sam2_gate`. Update comment count.

### 6. Cross-write ordering between fg/alpha/original is unsynchronized
**Files:** Resolve panel + AE host

Same partial-update risk as #1, even with atomic individual writes — viewer can read across versions. Most visible with FG SOURCE = "source" because the substitution depends on `original.png` matching `fg.png` semantically. Mitigated in practice by the viewer's poll cadence (50ms) being faster than the host's render cadence, but a slow render frame creates a window.
